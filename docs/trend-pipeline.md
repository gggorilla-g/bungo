# 伸びている動画を見つけて、しくみを自前で作り直す流れ（案。2026-11-27 時点、まだ定期では動かしていない）

持ち主 2026-11-27：「バズってて再現性のある動画をキャプチャして自動で動画制作→投稿を自動化できませんかね」

これまでは、持ち主が iPhone で録画した動画を送り、それを参考に作っていた（合体・箱・光の線など）。
ここでは「探す・撮る」を自動にして、作る・確かめる・上げるの既存の仕組みにつなぐ。

## 流れ

| 段 | すること | 道具 | 状態 |
|---|---|---|---|
| 1 探す | 決まった検索語で、今週のショートを再生数の多い順に読む | 持ち主の Mac の Chrome ＋ `tools/trend/search.js` | 11/27 に手で動作を確認 |
| 2 撮る | 上位の動画の数字（再生数・登録者・長さ・公開日・説明）と、1秒ごとのコマを読む | 同じく Chrome ＋ `tools/trend/capture.js` | 11/27 に手で動作を確認 |
| 3 しくみを書く | コマを見て「決まり・増え方・結末」を1〜3文で書く。作れるかを判定する | Claude | 11/27 に4本で試した（`docs/trend/2026-11-27.md`） |
| 4 作る | 自前の絵・音で作る（既存の型で足りれば spec、足りなければ新しい tools/<名前>.py） | pymunk・numpy・`tools/kalimba.py` | 型ごとに手で作っている（race.py、laser.py が見本） |
| 5 確かめる | 数値の検査 ＋ 出だし・真ん中・最後の絵を目で見る（`docs/vet-checklist.md`） | `tools/vet.py`、`tools/dupcheck.py` | ある |
| 6 上げる | `tools/up.sh` / `tools/upq.sh`。英語版は文字の差しかえ | GitHub Actions | ある |

毎日の定期の作業にするときは、1〜6 をこの文書どおりに回す（定期の作業は毎回まっさらな作業場で始まるので、ここに書いていないことは引きつがれない）。

## 守ること

- 動画はダウンロードしない。保存もしない。読むのは、ページの文字と、シークバー用の小さなコマだけ。コマはリポジトリに入れない（文字のメモだけ残す）。
- まねるのは「しくみ（決まり）」だけ。器の形・色・文字の置き方・題名の言い回し・音は自前のものにする。版権のあるキャラクター・ゲーム画面・曲・実写は使わない。
- 量を抑える：1日1回、検索は5語まで、動画の読みこみは10本まで。YouTube の利用規約（2023-06-01 付、2026-11-27 に確認）は
  「自動化された手段でのアクセス」と「コンテンツのダウンロード・複製」を禁じている。この手順は保存はしないが、自動のアクセスには当たりうる。
  コメント返信や Studio の巡回を Chrome で自動にしているのと同じ扱い。続けるかどうかは持ち主が決める。
- 同じしくみを少し変えただけの動画を並べない。YouTube の収益化の決まり（ヘルプ answer/1311392、2026-11-27 に確認）は
  「テンプレートで作ったように見える」「回ごとの変化が小さい」動画を対象外にしている。1本ごとに、問い・決まり・結末のどれかが違うこと。
- YouTube Data API で数字や検索結果を取らない（審査で申請した用途は投稿だけ）。
- 上げる前の確認の方式は、持ち主がまだ決めていない（下の「決まっていないこと」）。決まるまでは、新しい型は見せてから上げる。

## 1 探す

検索語（まずはこの5つ。伸びた語が見つかったら入れかえる）

- `physics simulation satisfying`
- `ball simulation`
- `satisfying simulation which color wins`
- `marble race simulation`
- `物理エンジン シミュレーション`

開くページ：`https://www.youtube.com/results?search_query=<語>&sp=EgQIAxgB`（今週・4分未満。ショートが棚で出る）。
開いたら `tools/trend/search.js` の中身を javascript_tool に渡す。再生数の多い順に8本が返る。

## 2 撮る

youtube.com のページを開いたタブで `tools/trend/capture.js` を渡す。

- `await META([...])`：数字の一覧。登録者に対する再生数の倍率（再生数÷登録者）を出して並べる。
  登録者が数人のチャンネルは倍率が大きく出すぎるので、再生数そのもの（目安：公開3日で5,000回以上）も合わせて見る。
- `await CAP('<ID>')` → screenshot：1秒ごとのコマを見る。見たら `CAPOFF()`。
- 音は取れない。音の参考がいるときは、今までどおり持ち主に録画を送ってもらう。ふだんは自前の音（`tools/kalimba.py` の bell・pad、カノン進行）を使う。

## 3 しくみを書く・選ぶ

メモの形（`docs/trend/<日付>.md`）：題名／チャンネル（登録者）／再生数と公開からの日数／長さ／しくみ（決まり・増え方・結末）／画面の文字／うちで作れるか／うちの既出と重なるか。

選ぶ物差し

- 2Dの物理・図形・数の決まりで説明できる（pymunk と numpy で描ける）
- 0秒で問いが分かり、途中で速さや数が上がり、最後に結末がある（`docs/vet-checklist.md` の「途中で拍が変わること」）
- 当たる・分かれる・消える、のたびに音を鳴らせる（当たった時刻と音を合わせる）
- 版権もの・実写・人物・ゲーム画面ではない
- うちの既出（`nazo/ballsim/published_*.txt`、`docs/video-ledger.md`）と同じしくみではない

新しい型は1日1〜2本まで（コードを書いて確かめるのに1本あたり数十分かかる）。

## 4 作る（新しい型を書くときの見本）

- `tools/laser.py`：器・玉・決まり・乱数さがし（search）・絵・音が1つのファイルに入っている。これを写して決まりを変える。
- `tools/race.py`：横長・長尺・段がある型。
- 音：`tools/kalimba.py` の `bell`（澄んだ音）と `pad`（下の持続音）。和音はカノン進行。同時に鳴らすのは3〜4音まで。残響は小さな部屋を 12〜14%。
- 乱数さがし：「◯秒前後で結末」「器からあふれない」「最後が接戦」などを点数にして、数十個の乱数から選ぶ。
- 英語版：`LANG_OUT=en` で文字だけ差しかえる。

## 5 確かめる

- 数値：長さ、音量（-16〜-12 LUFS）、高い音の割合（2.5kHz より上が数％以内）、玉が器の外に出ていない、題名の重複（dupcheck）。
- 目：出だし・真ん中・最後の絵を見る。文字のはみ出し・重なり、止まって見える時間がないか。
- 「おもしろいか」は数値では決められない。ここは人（持ち主）か、見せてからの反応で決める。

## 決まっていないこと（持ち主に確認中）

上げる前の確認の方式。

1. 見てから：見本を送り、「OK」が来たものだけ上げる
2. 待ってから：見本を送り、決めた時間（たとえば3時間）「だめ」が無ければ自動で上げる
3. 全自動：検査に通ったらすぐ上げ、あとで報告する
