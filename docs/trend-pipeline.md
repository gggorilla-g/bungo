## 決まっていること

- 上げ方：見本を持ち主に送り、その日の 21:00（日本時間）に公開する。上げるのは 20:40。それまでに持ち主が「だめ」と言ったものは上げない（「8 上げる」）。
  11/27 に「見てから／待ってから／全自動」の3つを出し、おすすめした「待ってから」で進めてよいと受け取った。
- 「だめ」に限らず、見本に直しの指摘（音が…、絵が…）が来たら、その版は上げない。直して、見本を送り直す。
- 音（11/27「電子音ぽすぎる。もっと物理的な音がいい」「二度うちは違う感じがする。恣意的な感じがする」）：
  硬い玉が板に当たる音（`tools/kalimba.py` の `knock`。当たる力の短い山から、物の響きを出す）。音の高さはカノン進行の和音の音。残響はほとんどかけない。
  鳴らすのは、絵の中で物が当たった瞬間だけ。1つの当たりに音は1つ。飾りの音（消える時の追加の音・決着の旋律・二度打ち）を足さない。
  材質は、木（`wood`）→ 竹（`bamboo`）→ 空洞のある木（`hollow`）を、動画1本ごとに順番に回す（11/27 聞き比べへの返事「2.3.4全部いいローテでいい」）。
  次の材質は `python3 tools/trendkit.py nextmat` が出す。使った材質は `nazo/trend/mat_log.txt` に書く。
- 絵（11/27「テクスチャと軌跡が安っぽい」）：ベタ塗りの四角・同じ太さの細い線で済ませない。物には材質、軌跡は光の残像。くわしくは `docs/vet-checklist.md` の「見た目の質」。
- 新しい型は1日1本（多くて2本）。作れる候補がない日は作らない。数より、勘所（`docs/vet-checklist.md`）。

## 毎日の流れ

### 0 用意
```
cd /home/claude/bungo        # 無ければ gh repo clone gggorilla-g/bungo /home/claude/bungo && cd /home/claude/bungo && git checkout kaizo3d-fridge
```

読むもの：この文書、`docs/vet-checklist.md`、`docs/trend/backlog.md`（候補の一覧）、`nazo/trend/queue.jsonl`（上げるのを待っている動画）。

### 1 きのうまでの残りを上げる（作る係）
`python3 tools/trend/release.py` … 順番待ち（`nazo/trend/queue.jsonl`）に残っている動画を、今日の 21:00 の公開予約で上げる。
ここに残っているのは、見本を送ったのに上げられなかったもの（1日の上限に当たった、20:40 に起きられなかった など）。
持ち主が「だめ」と言ったものがあれば、先に順番待ちから外して `nazo/trend/hold.txt` に理由つきで置く。

### 2 探す（探す係。持ち主の Mac の Chrome ＝ Claude in Chrome）
- 最初に tabs_context_mcp。新しいタブで作業し、終わったら閉じる。
- 検索語ごとに `https://www.youtube.com/results?search_query=<語>&sp=EgQIAxgB`（今週・4分未満）を開き、`tools/trend/search.js` の中身を javascript_tool に渡す。再生数の多い順に8本が返る。
- 検索語（5つまで。伸びた語が見つかったら入れかえる）
  `physics simulation satisfying` ／ `ball simulation` ／ `satisfying simulation which color wins` ／ `marble race simulation` ／ `物理エンジン シミュレーション`
- Chrome に届かないとき（Chrome が閉じている・拡張が応答しない）は、その旨を1行で報告して終える。ログイン操作はしない。
- Chrome が複数つながっていて選ぶよう言われたら、deviceId `277fb28a-1331-4f86-9747-5711e71e82f1` を select_browser で選ぶ。

### 3 撮る・しくみを書く（探す係）
- youtube.com のページを開いたタブで `tools/trend/capture.js` の中身を渡す。
  `await META([...])` で数字（再生数・登録者・長さ・公開日）。`await CAP('<ID>')` → screenshot で1秒ごとのコマ。見たら `CAPOFF()`。
- 読むのは1日10本まで。動画は再生もダウンロードもしない。コマは保存しない。
- `docs/trend/<日付>.md` に書く：題名／チャンネル（登録者）／再生数と公開からの日数／長さ／しくみ（決まり・増え方・結末）／画面の文字／うちで作れるか／うちの既出と重なるか。
- `docs/trend/backlog.md` に1行足す（しくみの名前・元の数字・状態「まだ」）。前に見たのと同じしくみは足さない（元の数字だけ書き足す）。
- commit して `tools/push_both.sh`。報告は、足した候補を1行ずつ。

### 4 選ぶ（作る係。`docs/trend/backlog.md` の「まだ」から1つ）
- 2Dの物理・図形・数の決まりで説明できる（numpy で描ける。押し合いが要るなら pymunk）
- 0秒で問いが分かり、途中で速さや数が上がり、最後に結末がある
- 当たる・分かれる・消える、のたびに音を鳴らせる
- 版権のあるキャラクター・ゲーム画面・曲・実写・人物ではない
- うちの既出（`nazo/ballsim/published_MOSO.txt`、`docs/trend/backlog.md` の「済み」）と同じしくみではない
- 倍率（再生数÷登録者）が高く、再生数そのものも多い（目安：公開3日で5,000回以上）

### 5 作る
- 見本は `tools/tiles.py`。`tools/trendkit.py`（絵・音・書き出し）を使い、`tools/<名前>.py` を1つ書く。
- まねるのは「しくみ」だけ。器の形・色・文字の置き方・題名の言い回しは自前にする。元の動画の文字（英語の実況など）を写さない。
- 決まりは、絵を作る前に数で試す。乱数を数十〜数百個回して、決着までの秒数・最初の出来事の時刻・最後の接戦の長さを見る。
  （11/27 の tiles：最初の決まり「3回ふむと割れる」は 10〜15 秒で終わり、最後の一騎打ちが1秒もなかった。「板の厚さをぜんぶ変える」にして、出来事がばらけた）
- 長さは 20〜35 秒。出だしから動いている。途中で拍が変わる理由は、絵の中の決まりにする（tiles は「1色おちるたびに、はねる高さが下がる」を点線で見せた）。
- 物の絵は `T.sprite`（飴玉）・`T.wood_stack`（木の板）など材質のあるものを使う。新しい物が要るときも、ベタ塗りにせず、光の向き（左上）・ふちの丸み・面ごとの明るさを入れる。
- 通った跡は `T.Trail`（遅い所ほど明るい残像＋玉の後ろの短い光）。同じ太さの線を引かない。光らせすぎない。
- 玉は `T.blit_mb` で置く（1コマの中の動きを平均する）。当たった所には、当たった物の色を映す（tiles の `top_light`）。物が動く理由（ばね・重さ）を絵にする（tiles の `dip`）。
- 画面の空いた所には、意味のあるものを置く（tiles は、これまでの高さの線と、その高さで落ちた色）。飾りだけの物は置かない。
- 音の材質：`python3 tools/trendkit.py nextmat` の答え（wood・bamboo・hollow のどれか）を、スクリプトの `MAT = os.environ.get("MAT", "＜材質＞")` に書き、`T.Audio(…, mat=MAT)` に渡す。
  `nazo/trend/mat_log.txt` に `＜名前＞ ＜材質＞` を1行足す（日本語版と英語版は同じ材質）。
- 音：`T.Audio(...).hit(t, u, vel=…)` を、当たった時刻そのままで呼ぶ（u は 0＝低い〜1＝高い。左右や大きさに対応させる。vel は当たりの速さに合わせる）。同時は3音まで。
  当たっていない時に音を鳴らさない（始まりの合図・終わりの旋律・消える時の追加の音を入れない）。
- 文字は `T.fit_text` で幅におさめる。日本語と英語は `T.tr("日本語", "English")`。英語版は `LANG_OUT=en`。
- 乱数は `T.pick_seed` で選び、選んだ数を `SEED` の既定値に書く（作り直しても同じ絵になる）。

### 6 確かめる
```
python3 tools/trend/check.py output/<id>.mp4     # 長さ・音量・高い音・余韻・無音・出だし・止まり・白とび
python3 tools/<名前>.py stills                    # 出だし・真ん中・最後の絵 → 目で見る
```
- 検査に NG があれば直す。直らなければ、その日は出さない。
- 絵を見る点：文字のはみ出し・重なり、玉が器の外に出ていない、止まって見えない、さびしくない、白く飛んでいない。
  縮小した全体だけでなく、等倍の切り出し（板・玉・軌跡のあたり）も見る。安っぽく見える所（ベタ塗り、ギザギザのふち、同じ太さの線）が残っていたら直す。
- 当たりの前後を 10 コマほど並べて見る（当たった瞬間に、絵がちゃんと応えているか）。
- 説明文の数字が、動画の中の数字と合っていること。説明欄に不等号（小なり・大なり）を入れない。
- 題名が既出と重ならないこと：`python3 tools/dupcheck.py check <キット> MOSO`（英語版は KAIDAN）。

### 7 見本を送る・順番待ちに入れる
- キット（題名・説明・タグ）を `nazo/manual/<名前>/<id>_upload.txt` に書く。題名は100字まで。
- `nazo/trend/queue.jsonl` に、日本語版（ch: MOSO）と英語版（ch: KAIDAN）を1行ずつ足す。`shown` は今日の日付。`build` は作り直すためのコマンド。
- `docs/trend/backlog.md` の状態を「済み（id）」に直す。`git add … && git commit … && tools/push_both.sh`（キットは push してからでないと上げられない）。
- 持ち主に送る（SendUserFile と SendUserMessage）：日本語版の動画、何を参考にしたか（題名・再生数・登録者）、しくみ、
  「今夜 21:00 に公開します。だめなら 20:40 までに『だめ』と返してください」の一言。
- send_later で、このチャットに 20:40（日本時間）の合図を予約する。文面は「公開の時刻。docs/trend-pipeline.md の 8 をする」。
  見本を送るのが 20:00 を過ぎたら（作るのが遅れた日）、予約はせず、あすの回の 1 に回す（順番待ちに残る）。持ち主が見る時間が 40 分は要る。
- 20:40 より前に、持ち主が「だめ」や直しの指摘を返してきたら、その場で `nazo/trend/hold.txt` に `id 理由` を書き（日本語版と英語版の両方）、順番待ちから外して、commit・`tools/push_both.sh`。
  （その場で push しておくと、このチャットが止まっても、あすの回が上げてしまわない）
  直せる指摘なら直して、見本を送り直す。hold.txt の行を消して順番待ちに入れ直すのは、送り直した時。
  send_later が使えないときは、その場で `python3 tools/trend/release.py` を実行して 21:00 の公開予約で上げ、
  持ち主には「止めたいときは、YouTube Studio のアプリでこの題名の動画を非公開にしてください」と伝える。

## 守ること

- 動画はダウンロードしない。保存もしない。読むのは、ページの文字と、シークバー用の小さなコマだけ。
- YouTube の利用規約（2023-06-01 付、2026-11-27 に確認）は「自動化された手段でのアクセス」と「コンテンツのダウンロード・複製」を禁じている。
  この手順は保存はしないが、自動のアクセスには当たりうる。量を抑える：1日1回、検索5語、動画10本まで。
- 同じしくみを少し変えただけの動画を並べない。収益化の決まり（ヘルプ answer/1311392、2026-11-27 に確認）は
  「テンプレートで作ったように見える」「回ごとの変化が小さい」動画を対象外にしている。1本ごとに、問い・決まり・結末のどれかが違うこと。
- YouTube Data API で数字や検索結果を取らない（審査で申請した用途は投稿だけ）。
- 上げるのは、検査に通り、絵を目で見たものだけ。迷ったら出さずに `hold.txt` に置く。
- 止まっている定期の作業（まとめ出し・Studio の巡回など）を動かさない。古い順番待ち（`nazo/ballsim/upload_queue.txt`）には触らない。
- 動画の削除、公開中の動画の変更（「だめ」と言われた動画を非公開にする以外）、設定の変更はしない。
- Chrome では、4時間ごとのコメント返信（2・6・10・14・18・22時の3分。11/27 持ち主が1時間ごとから変更）がチャンネルを切りかえている。探す係は Studio を開かない（検索と動画のページだけ）。
