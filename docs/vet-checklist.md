# 上げる前の確認（勘所）

オーナー 2026-11-23：「密度ないとしょーもないから。そういう勘所を押さえない動画はあげないで。密度が綺麗なんだから」

きっかけ：伸びていた歯車の花（96歯と41歯、花びら96枚）の続きとして、花びら16枚と11枚のまばらな版を作って上げてしまった。
元の動画の良さ（線が細かく重なって面になる密度）を落とした続きは、出す意味がない。

## 決まり

1. 上げてよいのは `nazo/ballsim/vetted.json` に登録した動画だけ。`tools/upq.sh` は、未登録の行と、作り直した絵が登録時と違う行をとばす。
2. 登録（`python3 tools/vet.py add <id> "見た点"`）の前に、いまのコードで作り直した動画の「出だし・真ん中・最後の絵」を目で見る。
3. 続きものは、1本目の良さが何だったかを先に書き出し、それを落としていないことを確かめてから作る。
4. 確認していないもの・勘所を外しているものは、順番待ちに入れず `nazo/ballsim/hold.txt` に理由つきで置く（消さない）。

## 見る点

模様が残る型（歯車の花・番号の何倍・バラ曲線・集まる線 など）
- 最後の絵が密か。線や点が細かく重なって面になっているか。目安：`vet.py fp` の「埋まり」が 25% 以上
  （歯車の花 96枚＝45%、まばらだった16枚＝10%、番号4倍の100点＝18%→240点に作り直して26%）。数字は線の太さや明るさでも変わるので、最後は目で決める
- 花びら・線・ボールの数は、1本目と同じかそれ以上か
- 色が白く飛んだり、ベタ塗りになっていないか（光は控えめに。オーナー 11/23「下品な光になりすぎないように」）

どの型でも
- 出だしから動いているか。終わりまで止まって見える時間がないか
- 音が1つずつ気持ちよく鳴り、和音に収まっているか（石・カロの音、和音を意識）
- 字や絵が画面からはみ出していないか、重なっていないか
- 法則どおりに動いているか（作為的な仕掛けにしない。ドミノはもたれかかって倒れる など）
- 説明文の数字が、動画の中の数字と合っているか

## 途中で拍が変わること（オーナー 2026-11-23）

「傾向としては、途中でリズムが変わるのがやっぱりエスカレーションがいいんだと思う」「いろんなクラシックバリエーションあってもいいね」

- 音が出る型は、途中で拍が細かくなる（4分→8分→16分 など）か、速くなる山を入れる。最後まで同じ拍のままにしない
- 拍が変わる理由は、絵の中の法則にする（ボールがふえる、辺がふえる、生える数が4倍 など）。理由なく速めない
- 曲は著作権の切れたクラシックから。同じ型の曲ちがいは作らない（オーナー 11/23「曲違いは作らなくていいです」）
