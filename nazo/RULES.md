# NAZO 台本の規約（在庫仕込み時にClaudeが従う）

チャンネル: 歴史・古代・自然の未解決の謎を約8〜10分で整理する。ずんだもん（VOICEVOX）、黒×赤。
運用: BUNGOと同じ在庫方式。台本はチャットで書き、Actionsは在庫から動画化と投稿だけを行う（実行時にLLMを呼ばない）。

## 線引き
- 事実（年代・数字・地名・固有名詞・寸法）は `nazo/state/texts/<id>.json` のWikipedia本文（日英）に書かれていることだけ。
  数字・カタカナ語・「」引用は `nazo/check.py` が機械照合し、本文に無ければ不採用。漢字の事実は書き手が自分で裏取りする。
- 説は自由に紹介してよいが、必ず「〜という説」「〜と考える人もいる」の形。どれが正しいか断定しない。
- 人名: 没後100年以上の歴史上の人物だけ名前を出す。近年の研究者・存命者は名前を出さず、説の中身で語る。
- 題材: 現代の実在人物・事件の被害者や遺族が関わるものは扱わない。宗教や民族を貶める説は紹介しない。
- 禁句（`check.py` の NG_PHRASES）: 真相は／正体は／宇宙人／陰謀 など、断定・煽り・誤情報に寄る言い回し。

## 構成（`check.py` が順序を検査）
1. toi（謎）: 挨拶なし。まず概要を4〜5文で言う: それは何か／いつ・どこで見つかったか／誰が見つけたか／今どこにあるか（見られるか）。
   動画の冒頭は自動で「世界の謎を10分解説。<題材名>。<logline>」と読むので、題材名を繰り返さない。
   概要のあとで、世間の思い込みを名指し→本文の事実で覆す（BUNGOの「裏切り」構造）→問い。
2. jijitsu（わかっていること）: 1〜2パート。物としての事実、記録の事実。
3. setsu（説）: 2〜4パート。冒頭で声が「ここから先は、説の話です。」と宣言する（自動挿入）。各説の弱点も添える。
4. shin_toi（残る問い）: 答えを言わない。誰でも次に一歩踏み出せる行動（公開資料を見る等）で終える。

## 文体
- 静かに語りかける。煽らない。流れる語り（前の文が次の文を呼ぶ）。短い言い切りと長めの説明を交ぜる。
- 1文は字幕1枚になる。60字前後までに収める。
- 合計2200〜4300字。見出しは15字以内、チャプター名として並べて引きになる言葉に。

## サムネイル（nazo/thumb.py が固定の型で自動生成）
- 型: 赤帯「世界の謎を10分で解説」＋巨大な見出し2行（2行目は赤）＋題材名＋右に実物の画像（`thumb_image`）。
- `thumbnail.main_copy` は4〜9字。読点「、」で2行に割れる言い回しにする（例「でたらめでは、ない」）。煽り・断定（正体は／真相は等）は使わない。
- `thumb_image` は、題材が一目でわかる実物の画像（写本のページ、遺物の写真など）を指定する。

## 仕込み手順
1. `python nazo/stock.py check <id> nazo/drafts/<id>.json` で照合とカナを確認
2. 誤読は台本をかなに開くか、`nazo/drafts/<id>_yomi.json` に {原文の文: 読み上げ文} で修正
3. `python nazo/stock.py push <id> nazo/drafts/<id>.json nazo/drafts/<id>_yomi.json`

## 画像の「寄り」
- 文字の形・部分の話をしている文では、その部分に寄った絵に切り替える。
- 書き方: `{"file": "...", "at": "その文の語", "zoom": [中心x, 中心y, 幅]}`（どれも画像に対する0〜1の割合、枠は16:9）。
- 寄りの位置は在庫を作るときに画像を見て決める（カタログのサムネで確認）。寄った次の文で全体に戻すと、どこの話かわかりやすい。

## サムネイルのコピー
- 見られなければ意味がない。スマホの小さな表示で一瞬で「何の話か」と「なぜ気になるか」がわかる言葉にする。
- 2行。1行目（白）＝つかみ、2行目（黄）＝何のことか。各行7〜8字まで。例「2000年前の / コンピューター」「誰も読めない / 謎の本」。
- 俗っぽくてよいが、事実に反すること・動画で扱わないことは書かない（「ついに解読」「呪い」など根拠のない煽りは禁止）。
- 詩的・ひねった言い回し（「〇〇では、ない」型など）は使わない。
- 見た目: 罫線などの飾りは入れない。文字はすべて四角の箱に入れる（極太）。

## 冒頭の構成（案内役 ホー博士）
- 冒頭: チャンネル名と題材を読み上げ → 最初のセクション（概要）を動く図解で → ホー博士のピンショットで名乗って本題へ。
- 台本に `host_intro` を書く。型:「こんばんは、ホー博士じゃ。今回は、〇〇の〇〇について話すぞい。なぜ〇〇な〇〇が〇〇なのか。わしと一緒に、〇〇していってくれ。」
- ホー博士の口調（じゃ・ぞい・わし）は host_intro だけ。本編のナレーションは今までどおりの文体。
- 最初のセクションには `motion`（地図・年号・寸法・語の箱・寄り）を付ける。地名は緯度経度で指定し、数字は本文と同じ値だけを出す。

## 声（ちび式じい）の規約で守ること
- クレジット「VOICEVOX:ちび式じい」を概要欄と画面に必ず入れる（自動）。無いと商用利用で40万円＋税の請求対象。
- タグ「ちび式じい」を付ける（自動）。
- 禁止：R-18/R-18G、差別・誹謗中傷、違法行為、第三者に不利益・不快感、政治・宗教の主張や攻撃。説の紹介で特定の宗教・民族を貶める言い方をしない。

## つかみ（hook）— ホー博士の名乗りまで見続けてもらうため
- 台本の先頭に `hook`（3〜4文）。タイトル読み上げより前に、暗めの画像の中央に大きな文字の箱で畳みかける。
- 書き方: `{"say": 読み上げる文, "text": 画面の2行（2行目が黄色）, "file": 画像}`。
- 型: ①いちばん引っかかる数字や事実 → ②まだ誰にもわかっていないこと → ③さらに奇妙な一点 → ④「〇〇は、いったい何なのか」。
- センセーショナルでよいが、事実照合の対象（本文にない数字・固有名詞は使えない）。「呪い」「ついに解明」など根拠のない煽りは禁止。

## 見出し（章題）の書き方
- 数字や名詞を並べただけの見出し（「45種類、241個」型）は伝わらない。何の数かを必ず書く：「45種類の文字、全部で241個」。
- 説の章は「〜という説」と書く（右上の区分札は廃止したので、見出しで説だとわかるように）。
- 15字以内。ひねった言い回しにしない。

## タイトル
- 型:「サムネの2行を足した言葉＋「題材名」＋【ホー博士の世界の謎10分解説】」。例:「誰も読めない謎の円盤「ファイストスの円盤」【ホー博士の世界の謎10分解説】」。
- 「〜なのか」「〜では、ない」のようなひねった問いかけにしない。
